Recipe: GitHub Actions

A CI step that writes short, readable lines to the job log and every event, Debug included, as structured JSON to a file. The workflow uploads the file as an artifact, turns warnings and errors into annotations, and the step’s exit code, not the log level, decides whether the job fails.

Samples in samples/github-actions/:

  • Test-JsonFiles.ps1 checks that every JSON file under a folder parses.
  • Write-LogAnnotations.ps1 reads the log file and writes the annotations and a job summary. It needs no module.
  • check-json.yml is the workflow.

The workflow

Section titled “The workflow”
  • The hosted runners have PowerShell 7.6+ and PSResourceGet. Pin the PoShLog version so that a new release does not change a build on its own; see Compatibility and installation.
  • The log goes to RUNNER_TEMP, outside the checkout, so it is never committed or picked up by other steps.
  • if: always() runs the last two steps also when the check fails, which is when the log matters most.

The logger

Section titled “The logger”
  • The console sink starts at Information and drops the timestamp, because the job log has its own.
  • Get-CompactFormatter -Rendered writes one JSON object per line (CLEF) with the rendered message in @m, the level in @l, the exception in @x and every property, the enriched Workflow and RunId included.
  • Exit code 1 means “the check found problems” and 2 means “the check could not run”. Both fail the step.

Missing events?

Section titled “Missing events?”
  • The artifact is empty or missing. The log file is written to RUNNER_TEMP only by the step that runs the script; check that -LogPath and the upload path name the same folder. upload-artifact without if: always() does not run after a failed step.
  • The last events are missing from the file. Close-Logger flushes it. Keep it in finally, and do not call exit inside try.
  • Debug events are not in the job log. That is on purpose: -RestrictedToMinimumLevel Information on the console sink. They are in the file, as long as Set-MinimumLevel is Debug.
  • The step is green although errors were logged. The log level does not fail a step; the exit code does. Set it with exit: shell: pwsh ends the step with the last $LASTEXITCODE, so the script’s exit code fails the step. A throw outside try fails it too, but then Close-Logger does not run.
  • Only ten annotations show. GitHub shows at most 10 warning and 10 error annotations per step. The rest are in the CLEF file and in the summary count.
  • An annotation is cut off after the first line. The message was not escaped; see above.
  • Install-PSResource cannot find the version. Prerelease versions need -Prerelease, and the version must exist on the PowerShell Gallery.
  • Still nothing. Call Enable-SelfLog before Start-Logger; Serilog then writes its own errors to the job log.

Verified

Section titled “Verified”

build/Test-Recipes.ps1 runs both scripts against the staged package, in a new pwsh process with GITHUB_WORKFLOW, GITHUB_RUN_ID and GITHUB_STEP_SUMMARY set. It checks the exit codes, the console lines, the CLEF events with their properties, the annotation lines with their escaping and the summary table. The workflow file itself is not run; its steps match the ones the check runs.
